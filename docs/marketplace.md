# 玩家摊位（Marketplace）

玩家可以把数量型物品（**鱼竿 / 鱼饵 / 蛋壳**）以灵玉标价挂在全服摊位上。
布尔型物品（锦囊、节日礼包、九张珍品）**不**上架——卖一次就清空，对玩家不公平；灵玉**不**当物品卖（自买自卖就是刷钱）。

---

## 1. 触发指令

DSL 规则定义在 [`bot/rules/main.ling`](../bot/rules/main.ling)。

| 玩家输入 | 动作 | 实现细节 |
|---|---|---|
| `摊位` / `摆摊` | **首屏菜单**：按物品分组的全服在售统计 | `$列出挂单$ agg=1` |
| `摊位鱼竿` / `摊位鱼饵` / `摊位蛋壳` | 该分类下所有挂单（前 20 条） | `$列出挂单$ item=物品` |
| `摊位@某人` | 该玩家摊位上的**全部**挂单（不限条数） | `$列出挂单$ seller=QQ` |
| `我的摊位` / `我的挂单` | 自己挂的挂单索引 | 直接读 `啊/摊位/索引/卖家/<QQ>` |
| `查挂单#<id>` | 单条挂单详情 | `$查挂单$` |
| `上架<物品><数量>个单价<价格>` | 调 `$上架挂单$`，24h 默认 | 返回挂单号 |
| `买#<id> [数量]` | 调 `$购买挂单$`，原子撮合 | — |
| `撤单#<id>` | 调 `$撤单$`，库存退回卖家 | — |

### 菜单样例

```text
玩家: 摊位
苏苏: ═════ 苏苏的摊位 ═════
      全服在售 4 条 · 共 14 件
        鱼竿 2 条 · 5 件
        鱼饵 1 条 · 6 件
        蛋壳 1 条 · 3 件
      ┈┈┈┈┈┈┈
      发「摊位鱼竿/鱼饵/蛋壳」看分类
      发「摊位@某人」看 TA 的摊位
      发「我的摊位」看自己挂的

玩家: 摊位鱼竿
苏苏: ═════ 苏苏的摊位 · 鱼竿 ═════
      142301-MXQR 鱼竿 3/3 50 123456
      142301-NPQR 鱼竿 2/2 55 789012
      ┈┈┈┈┈┈┈
      #<挂单号> 买<数量>

玩家: 摊位@123456
苏苏: ═════ 灵灵 的摊位 ═════
      142301-MXQR 鱼竿 3/3 50 123456
      142301-OPQR 蛋壳 1/1 100 123456
      ┈┈┈┈┈┈┈
      #<挂单号> 买<数量>
```

- `agg=1` 模式同时承担**懒清理**职责——扫到过期挂单就退款、改 status、下全局索引，**不发后台扫描**。
- `摊位@某人` 模式**不**受 20 条全局上限约束（该玩家摊位通常 <10 条，`@某人` 调用方想看全部）。

## 2. 摊位图卡（market_card）

首屏和 `摊位@某人` 两条 trigger 会**额外**调一次 `$市场图卡$` 工具，画一张 **150 像素宽**的 PNG 小卡片 inline 跟着文字发出。
卡片直接用 Pillow 画到 `BytesIO`、base64 编码、以 `base64://` URL 返回，**不**写磁盘、不依赖 linling 和协议端容器之间的共享文件系统。

- 标题用深棕色字：「苏苏的摊位」/「<QQ> 的摊位」
- 每个分类一行 + 专属色块（鱼竿黄 / 鱼饵绿 / 蛋壳白）
- 行内：左物品名、右 "N条·M件"（首屏）或 "left/total 单价灵玉"（@某人）
- 1px 米色边框、奶白底色，与聊天背景自然融合
- 空菜单 / 没人挂单 → 仍然返回一张 150×60 的小占位图，避免缺图时降级报错

DSL 用法：

```text
图:$市场图卡 $                   # agg 聚合
图:$市场图卡 seller %AT0%$       # @某人
±img=%图%±                       # emit 图（与文字同 handler，合并为一条多段消息）
```

`$市场图卡$` 同样承担**懒清理**——`摊位` 和 `摊位@某人` 是常用命令，顺手 sweep 过期挂单最经济。

### 图卡字体

图卡用 Pillow 动态渲染中文，**不能**靠 Pillow 自带的位图兜底（位图只支持 ASCII，中文会渲染成豆腐块）。字体发现顺序：

1. `ctx.extras["market_card_font"]` —— 启动时显式注入的 TTF/OTF 路径
2. `data/fonts/*.otf|ttf` —— 仓库自带的 [Noto Sans SC Regular 子集](https://github.com/notofonts/noto-cjk/tree/main/Sans/SubsetOTF/SC)（OFL 协议可商用，~8 MB）
3. Pillow `load_default()` —— 仅 10px ASCII 位图，中文成方块并打 warning 日志

更换字体：把 `.otf`/`.ttf` 放入 `data/fonts/` 即可，或通过 `ctx.extras["market_card_font"]` 指定任意绝对路径。

## 3. 核心实现与交易事务

- 核心工具位于 [`packages/tools-stdlib/src/linling_tools_stdlib/trade_ops.py`](../packages/tools-stdlib/src/linling_tools_stdlib/trade_ops.py)：
  - `$上架挂单$`
  - `$购买挂单$`
  - `$撤单$`
  - `$列出挂单$`
  - `$查挂单$`
- 所有写操作走 `SqliteKVStore.transaction()` 上下文管理器配合 `_tx_lock`，保证「检查库存 → 扣买家灵玉（含 4% 手续费）→ 加卖家灵玉 → 减挂单 left」整套动作原子完成，杜绝超卖。
- 4% 服务费沿用 `灵玉划转` 的传统（系统账户收），**卖家付**（卖家设置 `price_each` 是期望到手的净额，买家付 `ceil(price_each * 1.04)`）。
- **过期懒清理**：撮合与列出时检查 `expire_at`，过期则自动置 `status="expired"` 并退库存，无须额外的后台扫描器线程。
- **风控规则**：
  - 禁止自买自卖
  - 同 `(buyer, listing)` 冷却时间为 1 小时
  - 每个卖家最多同时存在 10 条活跃挂单
  - 单笔交易 > 1999 灵玉自动写入 `啊/摊位/大额` 留痕
  以上均在 Python 工具层强校验，规则层无法绕过。

## 4. KV 存储布局

```text
啊/摊位/挂单/<list_id>      → JSON  {seller, item, total, left, price_each, ...}
啊/摊位/索引/全局/active     → JSON  [list_id, ...]  全服活跃挂单
啊/摊位/索引/卖家/<QQ>       → JSON  [list_id, ...]  卖家维度的索引
啊/摊位/购买冷却/<list|buy>  → str   ts              1h 冷却
啊/摊位/大额/<ts>            → JSON  记录            大额交易留痕
```

WebUI 的 KV 浏览器会自动展示 `啊/摊位/` 命名空间，可供管理员直接浏览与排障。
