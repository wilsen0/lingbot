---

## Reporting a Vulnerability

We take the security and integrity of **linling** seriously. If you discover a vulnerability or security issue, please do **NOT** report it through public GitHub issues or discussions.

Instead, please report security issues responsibly using one of the following methods:

1. **GitHub Private Vulnerability Reporting**:
   - Navigate to the repository's **Security** tab.
   - Click on **Advisories**, then **Report a vulnerability**.
   - Fill out the details including proof-of-concept, impact, and affected components.

2. **Email Disclosure**:
   - If GitHub Advisories is unavailable, please reach out to the project maintainers privately.

---

## What to Include

To help us triage and resolve the issue quickly, please include:
- A description of the vulnerability and its potential security impact.
- Step-by-step reproduction instructions or a minimal proof-of-concept script.
- Affected components (e.g., `packages/webui`, `packages/dsl`, `packages/core`).
- Your environment details (OS, Python version, dependencies).

---

## Response Timeline

- **Initial acknowledgment**: Within 48 hours of receipt.
- **Triage & Assessment**: Within 5 business days.
- **Patch & Release**: We will coordinate the release date with you and provide credit in the security advisory unless you request anonymity.
